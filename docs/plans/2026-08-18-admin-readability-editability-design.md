# 后台管理端可读性与编辑体验升级设计

## 目标

在不修改后端接口、实体和数据库结构的前提下，统一后台管理端的信息层级、列表操作和编辑体验，使站长能更快定位模块、查找记录、理解字段并安全保存修改。

## 设计原则

- 以现有 `AdminView`、`ResourcePanel`、`FieldInput` 和 `--adm-*` 设计令牌为基础渐进增强。
- 保留现有接口、鉴权、明暗主题、分页和批量操作行为。
- 通用能力优先沉淀到共享基座，专用面板逐步复用，避免重复实现。
- 编辑效率与数据安全同等重要：快捷保存、固定操作栏与未保存提醒必须同时存在。
- 所有新增交互支持键盘访问，并在移动端保持可用。

## 方案选择

采用“统一后台交互基座”方案：先升级全局视觉令牌与共享组件，再将文章、番剧、站点内容等专用面板接入统一规范。

未采用仅 CSS 美化方案，因为它无法解决搜索、错误状态和未保存提醒；未采用逐面板重做方案，因为它会增加重复代码并延续体验不一致。

## 架构概览

### AdminView

- 菜单元数据同时驱动侧栏、当前模块标题和模块说明，形成单一信息源。
- 侧栏提供菜单关键词搜索；移动端继续使用抽屉，选择菜单后自动关闭。
- 顶栏展示当前模块名称、说明与必要的上下文信息，不再固定显示“管理后台”。

### ResourcePanel

- 在现有通用资源列表上增加本地关键词搜索、结果数量、清空搜索和面板内错误重试。
- 搜索仅作用于当前已加载数据和 Schema 指定的展示列，不改变 API。
- 保留分页、多选、批量修改和固定操作列，并增强吸顶表头、选中反馈和空状态区分。

### FieldInput 与编辑弹窗

- `FieldInput` 统一字段标签、说明、必填标记、禁用与错误状态。
- `resourceSchemas` 支持可选的字段分组元数据；没有配置分组的 Schema 自动使用默认分组。
- 编辑弹窗按“基础信息、内容与媒体、状态与排序、系统信息”组织字段。
- 弹窗底部操作栏固定，支持 `Ctrl+S` / `Cmd+S` 保存。
- 打开编辑时保存规范化表单快照；有修改时关闭会提示放弃或继续编辑。

### 专用面板

- `ArticlesPanel`、`BangumiPanel`、`SiteContentPanel` 等保留现有业务逻辑。
- 统一使用后台设计令牌、标题栏、表单间距、保存状态和错误反馈。
- 优先移除硬编码亮色背景，确保明暗主题信息层级一致。

## 数据流

1. `menuGroups` 扩展模块说明元数据，派生当前模块信息和过滤后的菜单分组。
2. `ResourcePanel` 加载全量数据后，在 computed 中按展示列生成过滤结果，再进行前端分页。
3. 打开编辑弹窗时建立初始表单快照；字段修改后通过规范化值比较得到脏状态。
4. 保存成功后更新快照并关闭弹窗；保存失败保留当前表单与脏状态。
5. Schema 分组和字段说明只影响前端展示，不改变提交载荷。

## 错误与边界处理

- 列表加载失败时展示面板内错误、错误说明和重试按钮。
- 搜索无结果与数据库无数据使用不同空状态。
- 保存失败不关闭弹窗、不清空输入，并在保存区域显示错误。
- 登录过期继续走现有 `adminUnauthorized` 统一退出流程。
- 删除和批量操作保留现有确认与部分成功数量反馈。
- 未保存关闭提示覆盖遮罩点击、关闭按钮和 Escape；保存中禁止重复关闭。
- 小于等于 900px 时编辑弹窗改为全屏布局，表格仍允许横向滚动。

## 视觉与可访问性

- 后台字体使用清晰的中文系统字体栈，移除 `Comic Sans MS`。
- 收敛字号、圆角和阴影，提高表格信息密度和文字对比度。
- 交互控件提供统一 Hover、Active、Focus-visible、Disabled 和 Loading 状态。
- 图标按钮提供可访问名称；输入控件与 label 建立明确关联。
- 亮色与暗色均只使用 `--adm-*` 语义令牌，专用面板不再依赖固定白色。

## 测试策略

- 为菜单过滤、列表过滤、字段分组和脏状态比较编写纯函数测试。
- 为 `AdminView`、`ResourcePanel`、`FieldInput` 增加结构回归测试。
- 验证加载失败、空数据、无搜索结果、保存失败和未保存关闭流程。
- 检查亮色、暗色、900px 抽屉断点及小屏全屏编辑弹窗。
- 完成后运行：
  - `frontend/` 下 `npm run lint`
  - `frontend/` 下 `npm test`
  - `frontend/` 下 `npm run build`
  - `git diff --check`

## 实施顺序

1. 后台视觉令牌、字体和通用焦点状态。
2. 动态顶栏和侧栏菜单搜索。
3. 通用资源列表搜索、统计、错误与空状态。
4. 字段分组、脏状态、固定保存栏和快捷保存。
5. 专用面板视觉与反馈统一。
6. 全量测试、构建和响应式验证。

## 非目标

- 不新增或修改后端 API。
- 不变更实体字段和数据库 DDL。
- 不重做鉴权和权限模型。
- 不引入新的 UI 框架或状态管理依赖。
- 不改变前台页面视觉与交互。
