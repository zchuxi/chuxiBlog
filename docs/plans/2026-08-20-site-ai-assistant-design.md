# 站内 AI 助手设计

## 目标

把现有仅返回演示文案的 AI 助手，升级为可配置的站内问答功能：服务端检索已发布文章，将相关内容作为上下文交给 OpenAI-compatible 模型；模型未配置或不可用时仍提供站内检索降级结果。

## 架构

- 前端 `AiChatPanel.vue` 通过 `POST /api/front/ai/chat` 发送最近对话消息。
- 后端 `AiController` 负责请求校验与统一响应，`AiChatService` 负责文章检索、上下文截断、模型调用和降级回答，`AiProperties` 读取环境变量配置。
- 模型调用使用 JDK `HttpClient`，不新增 SDK 依赖；API key 只在后端配置。

## 数据流

1. 服务端校验消息数量、单条长度和总长度。
2. 从用户最后一条消息提取关键词，在已发布文章的标题、摘要、标签和正文中检索，最多取配置数量的文章。
3. 构造带有站点身份、引用文章上下文和对话历史的 chat-completions 请求。
4. 成功时返回模型文本与引用文章；未启用、无 key、超时或上游错误时返回检索摘要与可理解的降级提示。

## 错误处理与安全

- 以 IP 为维度限流，避免公开接口被滥用。
- 上游 URL、模型、超时、上下文数量均由服务端配置控制；不把 key 或上游原始错误返回给浏览器。
- 只检索已发布文章，正文按字符数截断，避免无界加载和超大请求。

## 前端交互

- 发送中显示状态并禁用重复提交，响应后自动滚动到底部。
- `Enter` 发送、`Shift+Enter` 换行；重置按钮清空对话。
- 保留现有弹窗视觉样式，补齐空、加载、错误和引用文章状态。

## 测试策略

- 后端单元/控制器测试覆盖校验、检索降级、上游成功和上游失败。
- 前端纯逻辑测试覆盖消息裁剪、请求参数、发送状态和重置行为。
- 按仓库约定运行 `mvn test`、`npm run lint`、`npm test`、`npm run build`。
